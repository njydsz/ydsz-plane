## 三、AI 能力专项（三轮演进）

| 阶段 | 状态 |
|------|------|
| 首次分析 | 规则引擎（关键词匹配 + 概率推断），**从未接入大模型** |
| 第二轮 | LLM 网关 + Function Calling + Agent 三模式 + Run 生命周期（**框架完整，但无触发器、写作仍是规则引擎**） |
| 本轮 | 触发器运行时补齐 + AI 写作接入 LLM + 实时光标（**端到端闭环**） |

### 本轮 AI 增强细节

**触发器运行时**
- `TriggerDispatcher`：领域事件 → 匹配 Agent.triggers → 创建 Run → 异步执行
- 四种触发：`mention`（@ 解析）、`assignment`、`event`（创建/状态变更/评论）、`schedule`
- 幂等：5 分钟去重窗口，避免重复触发
- 接入点：`CommentService.SetAgentTrigger()`，在评论创建后自动解析 @mention

**AI 写作真实化**
- 三个端点全部优先走 LLM，失败时退回规则引擎（用户无感知）
- 续写：基于上下文与全文生成，限制 token 上限
- 改写：formal/concise/fluent/expand 四种风格
- 语法：校对并返回结构化 `GrammarIssue`（偏移/原文/替换/原因）

**实时光标**
- 编辑器 `onSelectionUpdate` → 归一化 → 节流广播 → WebSocket 分发 → 远程渲染
- 协作者色板稳定（基于 userId 取模），标签显示姓名

## 七、结论

三轮落地后，ydsz-plane 对 Plane 的**综合复刻度由约 70% 提升至约 88%**。

**本轮核心突破**：
1. **AI 写作真实化**——三个写作端点从规则引擎升级为真实 LLM 调用，并保留规则引擎兜底（优雅降级）
2. **Agent 触发器运行时**——四种触发方式的实际执行器，`@mention` 已接入评论链路
3. **实时光标**——协作者存在感从「头像列表」升级为「光标级可见」

剩余差距进一步收窄，主要集中在 **CRDT 字符级共编**（需引入 Y.js/Automerge 运行时）与 **Marketplace / 原生客户端**（生态与分发形态，非功能缺失）。

ydsz-plane 在**研发效能度量**（DORA/缺陷分析/工作量热力图/项目对比）、**工程治理**（DLQ 监控/审计报表/国密合规/RLS/God Mode）与 **AI 基础设施**（主/备 LLM 容灾 + 规则引擎兜底）三方面保持了显著差异化优势。
