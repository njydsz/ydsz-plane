## 二、本轮落地（第七轮）

### Wails v3 原生桌面客户端

**技术选型**：Wails v3（Go 桌面框架）—— 后端纯 Go，最大化复用现有 Go 代码库。

**对比其他方案**：

| 方案 | 体积 | 后端 | 工具链 |
|------|------|------|--------|
| Electron | 80-150MB | Node.js | Node |
| Tauri | 10-20MB | Rust | Rust + Node |
| **Wails v3** | **15-20MB** | **Go** | **Go** |

**实现内容**

| 模块 | 职责 |
|------|------|
| `main.go` | 应用入口：窗口创建 + 服务注册 + 资源嵌入 |
| `service_platform.go` | 平台信息（OS/架构/版本/主机名/目录） |
| `service_notification.go` | 原生系统通知（封装 Wails notifications 服务） |
| `service_window.go` | 窗口控制（标题/最小化/最大化/置顶/焦点/外部链接） |
| `service_updater.go` | 应用内自动更新 |
| `common.go` | 版本号 + 桌面日志（写入 `%APPDATA%/YdszPlane/logs`） |
| `wails.json` | Wails v3 配置（窗口/资产/devMode） |
| `Taskfile.yml` | 构建任务（dev/build/package 跨平台） |
| `web/src/lib/desktop.ts` | 前端桥接层（运行时检测 + 服务调用 + 浏览器降级） |

**前端桥接**（`web/src/lib/desktop.ts`）：

```ts
import { initDesktop, notify, openExternal, isDesktop } from "@/lib/desktop";

await initDesktop();  // 检测 Wails 环境，浏览器下自动降级

if (isDesktop.value) {
  await notify("任务已完成", "您有 3 个待处理事项");
  await openExternal("https://github.com/njydsz/ydsz-plane");
}
```

**已验证**：`go build -o bin/ydsz-plane.exe .` 成功产出 **18MB** 可执行文件。

## 六、结论

七轮落地后，ydsz-plane 对 Plane 的**综合复刻度由约 70% 提升至约 97%**。

**本轮核心突破**：Wails v3 原生桌面客户端。相比 Electron（150MB），Wails 产物仅 **18MB**，且后端直接复用现有 Go 代码库，无需引入 Rust/Node 工具链。

剩余差距已收窄至：移动端（按要求不做）、AI 流式输出（SSE）、敏感数据扫描、跨节点 CRDT 与桌面签名公证——均属可选项或需持续迭代的领域。

ydsz-plane 在**研发效能度量**、**工程治理**、**AI 基础设施**、**迁移能力**、**生态**、**实时协同**与**客户端形态**七个方面均建立了显著差异化优势。
