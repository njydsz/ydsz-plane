# 11 · 仪表盘与效能度量设计（S9/S11）

> 对应 Sprint 9（仪表盘 P0 卡片）、Sprint 11（度量+DORA）
> PRD §9.1 / §9.8 落地规格

---

## 1. 仪表盘框架

### 1.1 数据模型

```sql
dashboard_configs(id, workspace_id, scope[project|workspace], ref_id,
                  name, layout JSONB,            -- [{widget_id,x,y,w,h}]
                  owner_id, is_default, role_visibility JSONB)
widgets(id, dashboard_id, type, config JSONB,    -- type 决定渲染器与数据接口
        position INT, size TEXT)
```

### 1.2 卡片注册表（前端渲染器 ↔ 后端数据接口一一对应）

| type | 数据接口 | 刷新 | 优先级 |
|------|----------|------|--------|
| `project_overview` | `GET /metrics/overview?project=` | 实时(缓存30s) | P0 |
| `sprint_burndown` | `GET /sprints/{id}/burndown` | 实时 | P0 |
| `version_progress` | `GET /versions/{id}/progress` | 实时 | P0 |
| `module_distribution` | `GET /metrics/by-module?project=` | 1h | P0 |
| `quality_indicators` | `GET /metrics/quality?project=` | 1h | P0 |
| `risk_alerts` | `GET /metrics/risks?project=` | 实时 | P1 |
| `resource_load` | `GET /metrics/member-load?project=` | 4h | P1 |
| `velocity_trend` | `GET /metrics/velocity?project=` | sprint 结束 | P1 |
| `dora_summary` | `GET /metrics/dora?project=` | 每日 | P1 |
| `leadtime_scatter` | `GET /metrics/lead-time?project=` | 每日 | P2 |

- 每个卡片接口返回**自描述数据**：`{ value, series, unit, trend, threshold_state }`，前端渲染器不感知业务。
- 缓存策略：`dash:{dashboard}:widget:{id}` 按刷新频率 TTL；实时类 30s 短缓存防击穿（singleflight）。
- 预警规则：`alert_rules(dashboard_id, metric, op, threshold, channels)`；每日任务评估，越限 → 通知域。

### 1.3 交互能力
- 布局：gridstack.js 拖拽/缩放，保存即写 layout。
- 联动：点击图表元素 → 全局 filter store → 其他卡片请求携带该维度参数。
- 下钻：项目总览 → 单项目 → 单迭代 → 工作项列表（URL 参数传递过滤器）。
- 驾驶舱：全屏 + 轮播多仪表盘（30s 切换），仅只读 token 可分享大屏链接。
- 预设模板：敏捷项目 / 版本交付 / PMO 多项目（布局+卡片组合的 JSON 预置）。

## 2. 效能度量（bi 上下文）

### 2.1 指标计算口径（冻结定义，避免多口径打架）

| 指标 | 公式 | 数据源 |
|------|------|--------|
| 需求前置时间 Lead Time | completed_at − created_at（自然日，P50/P85） | issues(requirement) |
| 开发周期 | 首次进 started − completed_at | issue_activities |
| WIP | 当前 started 计数 | issues 实时 |
| 吞吐量 | 每周 completed 数 | issues |
| 流动效率 | 开发周期 / 前置时间 | 派生 |
| 缺陷密度 | 缺陷数 / Σ需求故事点 | issues |
| 逃逸率 | found_phase=production|customer 占比 | issues(defect) |
| 返工率 | reopened 缺陷 / 总缺陷 | issue_activities |
| 缺陷龄 | now − created_at（未关闭），按状态分桶 | issues |
| Velocity | sprint done_points | sprint_snapshots |
| DORA-DF | 生产部署次数/周期 | deployment_events |
| DORA-LT | commit→deploy 均值 | deployment_events |
| DORA-CFR | 失败部署占比 | deployment_events + 关联缺陷 |
| DORA-MTTR | 故障→恢复均值 | deployment_events + incident 缺陷 |

### 2.2 采集与存储

```sql
metric_snapshots(id, workspace_id, project_id, granularity[daily|sprint|version],
                 ref_id, metric, value NUMERIC, dimensions JSONB, snapshot_date)
deployment_events(id, workspace_id, project_id, env, status[success|failed],
                  commit_sha, started_at, deployed_at, source, created_at)
```

- 每日 01:30 聚合 Job 写快照（幂等 upsert）；实时类指标直查 + 缓存。
- DORA 数据源：专用 Webhook 端点 `POST /hooks/deployments`（CI/CD 推送），HMAC 校验。
- 数据校准：admin 可对快照写修正记录（`metric_adjustments`，不覆盖原值，查询时叠加），全程审计。

### 2.3 报表视图
- 速率图（近 6–10 sprint 柱状+均线）、CFD（by_state_group 堆叠面积）、控制图（lead time P50/P85 控制线）、散点图（完成日×周期）。
- 模板：工程效能 / QA 质量 / PMO 战略三预设；全部支持 API 导出（对接外部 BI）。

## 3. 性能与权限

- 聚合查询全部走快照表或缓存；实时卡片 SQL 必须有索引覆盖（`EXPLAIN` 纳入 PR 评审附件）。
- 效能数据权限 = 项目成员可见；PMO 跨项目视图需 workspace admin。
- 大屏分享链接：只读、可吊销、有效期可选。
