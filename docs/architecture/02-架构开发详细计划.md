## 1. 计划假设

- **团队配置**：架构师/Tech Lead ×1、后端 ×2、前端 ×2、QA ×1、PM ×1（兼设计）。共 7 人。
- **迭代节奏**：2 周一个 Sprint，每周 5 个工作日；后端/前端并行，联调在迭代后半段。
- **总周期**：24 周（12 个 Sprint），覆盖 MVP（S1–S7）+ Phase 2 核心（S8–S12）。
- **技术基线**：《01-系统架构设计.md》全部 ADR 已评审通过。
- PRD 中明确"不做/延后"的项（实时协作编辑、测试用例管理、IM 原生机器人、移动端）不在本计划内。

## 5. 质量保障

- **Definition of Done**：代码评审通过；单测覆盖领域服务 ≥70%；接口含集成测试；E2E 覆盖核心旅程（PRD §11 三条用户旅程）；文档同步更新。
- **测试金字塔**：领域不变量单测 → API 集成测试（testcontainers）→ Playwright E2E。
- **每迭代固定动作**：Sprint 第 2 周周三联调冻结、周五演示 + 复盘；缺陷不过夜（P0）。
- **性能门禁**：CI 中 k6 冒烟（核心接口 P95 ≤200ms）；S7/S12 两次全量压测。
- **安全门禁**：依赖扫描（govulncheck / pnpm audit）、CI 静态检查、S10/S12 两次专项安全测试。
