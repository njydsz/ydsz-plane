## 一、逐 Sprint 审计结果

### S1 — M0 工程基座  ✅ **通过 (9.0/10)**

**已确认的交付：**
- Gin 路由器 + 8 项中间件链（SecurityHeaders → RequestID → Recovery → CORS → AccessLog → Metrics → Auth → RBAC）
- 配置管理：Viper 12-Factor App，环境变量覆盖，生产密钥严格校验
- 8 项安全响应头：CSP、X-Content-Type-Options、X-Frame-Options、X-XSS-Protection、Referrer-Policy、Permissions-Policy、COOP、CORP
- JWT HS256 认证 + Refresh Token 轮换
- Redis 滑动窗口限流（fail-open）
- Prometheus 指标收集（5 个 Collector）
- Docker Compose 全栈 + 多阶段 Dockerfile（非 root）
- Swagger UI（仅开发环境暴露）

**发现的问题：**
- ⚠️ `web/node_modules/flatted/golang/pkg/flatted` 子模块的 go.mod 与主模块冲突，导致 `go test ./...` 在包含 web/ 时返回 FAIL
- ⚠️ CI/CD 缺失：`.github/workflows/` 仅有 `db-comments-check.yml`，缺少 Go build/test/lint/vet、govulncheck、pnpm audit 的自动化 CI

**建议修复：**
1. 在 `go test` 调用中显式排除 `web/node_modules`
2. 创建完整的 `ci.yml` 流水线

### S2 — 租户与项目骨架  ✅ **通过 (8.8/10)**

**已确认的交付：**
- 4 角色 RBAC（Owner/Admin/Member/Guest）+ 16 项权限矩阵
- WorkspaceMembershipStore 正确抽象（非成员统一 403 防探测）
- JWT Access + Refresh 双令牌（轮换 + 类型校验）
- bcrypt Cost=12（≈250ms/哈希）
- 密码重置流程（模糊化 202 防用户枚举）
- 注册开关（`features.registration_open`）
- API Token 管理（JWT → API Token 复合解析，Scope 二次防线）
- 审计日志（全量管理操作记录）

**代码亮点：**
- RBAC 中间件的 API Token scope 双重校验（`CtxAuthKind == "api_token"` → 范围收敛检测）
- `bearerToken()` 三层提取：Authorization Header → X-Api-Key → Cookie

**发现的问题：**
- ⚠️ Refresh Token 未落地 Redis 黑名单/轮换存储（当前仅靠类型+过期校验）

## 六、结论

S1-S12 全系列代码架构设计优良，安全纵深在关键模块（Webhook SSRF、XSS 净化、RBAC）达到大厂水平。主要短板在 **工程自动化（CI/CD）** 和 **测试覆盖率** 两个维度，这与早期快速迭代阶段的取舍一致。

核心风险可控：无 SQL 注入、无已知 XSS 漏洞、SSRF 防护到位、依赖版本健康。建议按照上述优先级路线图逐项推进修复，预计 8 周内可将综合评分从 B+(7.7) 提升至 A-(8.5+)。
