# 14 · 测试策略与质量保障（全周期）

> 参考：Google《Software Engineering at Google》测试规模分类、测试金字塔实践

---

## 1. 测试金字塔与工具

| 层 | 占比 | 工具 | 内容 |
|----|------|------|------|
| 单元 | 60% | go test + testify / vitest | 领域规则（WBS、状态机、进度回写、DSL 求值）、纯函数 |
| 集成 | 30% | testcontainers（PG/Redis/NATS） | 仓储 SQL、RLS 隔离、API 端到端（httptest）、事件链路 |
| E2E | 10% | Playwright | PRD §11 三条用户旅程 + 核心管理流 |

- 覆盖率门禁：领域层 ≥70%，整体 ≥50%（ratchet）。
- 测试命名：`Test<Unit>_<Scenario>_<Expectation>`；表驱动；禁止 sleep 同步（用 eventually 断言）。

## 2. 关键专项测试清单

**租户隔离（最高优先级）**：
- 跨空间 ID 访问 → 404（每个资源类至少 1 例）
- RLS 生效验证：直连低权账号查询他租户数据返回空集
- 连接池复用场景：同连接先后服务两租户，上下文无串扰

**并发与幂等**：
- 迭代双启动并发 → 仅一成功
- 同 Idempotency-Key 重放 → 单条记录
- 乐观锁并发更新 → 一方 409
- 看板并发拖拽 → sort_order 不重排错乱
- 自动化同 issue 规则串行执行

**状态机**：
- 全部内置模板流转路径正向遍历
- 非法流转全部拒绝（矩阵穷举）
- 缺陷 required_fields 强制（已修复必 root_cause；待验证必 fix_version）

**事件链路**：
- Outbox 不丢：模拟 worker 宕机 → 恢复后补投
- 消费者幂等：重复投递同 event_id → 无副作用
- 自动化防循环：A→B→A 链路深度截断

**安全**：
- OWASP Top10 用例集（注入/XSS/越权/SSRF/限流）
- Webhook 签名伪造、时间戳重放
- 密码策略与锁定；Token 吊销即时生效

## 3. 性能测试

- 造数脚本：`scripts/seed-scale.sh`（100 万工作项 / 10 万评论 / 1000 用户）。
- k6 场景（读写比 9:1）：登录、项目首页、看板加载、详情、列表过滤、搜索、创建/流转。
- 门禁：CI 每夜冒烟（1 万数据，P95 基线对比 ±20%）；S7/S12 全量压测出报告。
- 慢查询：`pg_stat_statements` 周巡检，>100ms 均值进优化队列。

## 4. 前端质量

- 组件：vitest + Testing Library（ui 包组件全覆盖）。
- E2E 矩阵：Chrome / Edge / 360 安全浏览器。
- 视觉回归：Storybook + 截图对比（关键页面）。
- web-vitals 上报纳入 SLO（LCP/INP/CLS）。

## 5. 缺陷管理（吃自己的狗粮）

- 项目自身用 Ydsz Plane 管理缺陷（v0.1 起）。
- 分级：P0 阻断发布（数据丢失/安全/核心流不可用）→ 不过夜；P1 当迭代修；P2 排期；P3  backlog。
- 每个 P0 必须有复盘记录（root cause + 预防措施），关联根因分类字段。

## 6. 质量节奏

- 每 Sprint：周三联调冻结 → 周四全量回归 → 周五演示。
- 每月：依赖扫描报告、覆盖率趋势、SLO 回顾。
- 发布前：checklist（测试报告/压测/安全/回滚方案/文档）逐项签字。
