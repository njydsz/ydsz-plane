# 03 · 工程基座与开发规范（S1）

> 参考标准：12-Factor App、Google SRE、Uber Go Style Guide、Conventional Commits、SemVer、Trunk-Based Development（GitHub Flow）

## 1. Monorepo 结构（最终定稿）

```
ydsz-plane/
├── cmd/
│   ├── api/main.go            # API Server 入口
│   ├── worker/main.go         # Asynq Worker 入口
│   └── migrate/main.go        # 迁移执行入口（也可走 golang-migrate CLI）
├── internal/
│   ├── domain/                # 领域层：实体/值对象/领域服务/仓储接口/领域事件
│   │   ├── iam/  workspace/  project/  issue/  sprint/  version/
│   │   ├── intake/  document/  kb/  notification/  search/
│   │   ├── automation/  webhook/  bi/
│   │   └── shared/            # 共享内核：Tenant、UserID、Event 基类、错误码
│   ├── application/           # 应用服务：用例编排、事务边界（UnitOfWork）、DTO
│   ├── infrastructure/
│   │   ├── persistence/       # pgx 仓储实现 + dialect/（pg|dameng|kingbase）
│   │   ├── cache/  search/  queue/  storage/  mailer/  im/
│   │   └── telemetry/         # 日志/指标/追踪初始化
│   └── interfaces/
│       ├── http/              # Gin handler / request binding / response envelope
│       ├── middleware/        # auth/tenant/rbac/ratelimit/audit/idempotency
│       └── ws/                # WebSocket 扇出
├── pkg/                       # 可外部引用：crypto（SM2/3/4 抽象）、validator、jsonx、errs
├── api/
│   ├── openapi/               # 生成的 OpenAPI 3.0 规范（swaggo 产出）
│   └── events/                # 事件目录 JSON Schema（见 09/12 文档）
├── web/                       # 前端（pnpm workspace）
│   ├── src/  packages/ui/  packages/editor/  packages/design-tokens/
├── migrations/                # 0001_init.up.sql / .down.sql 递增编号
├── configs/                   # config.example.yaml，各环境 .env.example
├── scripts/                   # dev-up.sh、seed.sh、reindex.sh、backup.sh
├── deployments/
│   ├── docker-compose.yml  docker-compose.full.yml
│   ├── helm/                  # Phase 3
│   └── nginx/  prometheus/  grafana/
└── docs/
```

**依赖方向铁律**（CI 用 `go-arch-lint` 强制）：
`interfaces → application → domain ← infrastructure`，domain 不得 import infrastructure；模块间禁止跨包引用 internal 实体，只能经 application 服务接口。

## 2. 配置管理（12-Factor）

- 一切配置走环境变量；`configs/config.example.yaml` 仅作模板与本地开发默认值。
- 启动时 `viper` 加载并**校验必填项**，缺配置直接 fail-fast。
- 密钥不落库不落仓：本地 `.env`（gitignored），生产用 Docker secret / K8s Secret。
- 配置分组：`server / database / redis / nats / es / minio / smtp / im / auth / observability / feature_flags`。
- Feature Flag：`feature_flags.search_enabled` 等，未就绪功能线上关闭但代码可合并（ trunk-based 前提）。

## 3. 分支与发布策略（Trunk-Based）

```
main（受保护，永远可发布）
 ├── feature/xxx      → PR → squash merge
 ├── fix/xxx          → PR → squash merge
 └── release/v0.1     → 仅 cherry-pick 修复 → tag v0.1.0
```

- PR 门槛：CI 全绿 + 1 人 Approve（核心域 2 人）+ 无 unresolved 评论。
- 提交信息：Conventional Commits（`feat/fix/docs/refactor/test/chore/perf`），CI 用 `commitlint` 校验。
- 版本号：SemVer；CHANGELOG 由 `git-cliff` 从提交记录自动生成。
- 镜像 tag：`v0.1.0`、`v0.1.0-rc.1`、`sha-<short>`、`latest`（仅 main）。

## 4. CI/CD 流水线（GitHub Actions）

```
PR 触发:  lint → unit test(race) → build → e2e-smoke(testcontainers)
main 推送: 以上全部 + e2e-full + 镜像构建推送 + 部署 staging
tag 触发:  全量测试 + 多架构镜像(amd64/arm64) + Release 草稿 + 部署 prod(手动批准)
定时(夜):  依赖扫描 govulncheck/pnpm audit + k6 性能冒烟 + 数据库迁移回滚演练
```

质量门禁（未达标阻断合并）：
- `golangci-lint` 0 error；单测覆盖率领域层 ≥70%、整体 ≥50%（ratchet 只升不降）
- 前端 `eslint + prettier + vue-tsc` 通过；Playwright 冒烟通过
- OpenAPI 规范 diff 检查（breaking change 需显式标注 `BREAKING:`）

## 5. 开发环境一键启动

```bash
make dev          # docker compose up pg redis nats + 热重载(air) api/worker + vite dev
make seed         # 演示数据（1 空间/3 项目/500 工作项/2 迭代/1 版本日）
```

前端统一 `pnpm`（`packageManager` 字段锁版本），Node 版本用 `.nvmrc` 锁定 20.x；Go 版本 `go.mod` 锁定 1.22。

## 6. 编码规范（落地到大厂标准的子集）

**Go**（Uber Style Guide 精选强制项）：
- 错误必须处理或显式 `_ =` 注释原因；禁止裸 `panic`（仅 main/初始化允许）
- context 作为首参传递，不存 struct；DB 操作必须带 ctx 超时（默认 5s）
- 接口在**使用方**定义（仓储接口在 domain 层，实现放 infrastructure）
- 表驱动测试；Mock 用 `gomock` 生成，禁止手写散落 mock
- 结构体字段禁止可变共享：领域实体的方法返回副本

**TypeScript/Vue**：
- 严格模式 `strict: true`；禁止 `any`（eslint `@typescript-eslint/no-explicit-any` error 级）
- 组合式 API + `<script setup lang="ts">`；组件名多词；props 必须类型化
- API 类型由 OpenAPI 生成（`openapi-typescript`），禁止手写接口类型漂移
- 组件只允许依赖 `packages/ui` 门面，禁止页面直接 import Element Plus

**SQL/迁移**：
- 迁移只增不改：已合入 main 的迁移文件禁止编辑，修正走新迁移
- 每个迁移必须可回滚（`.down.sql` 非空），破坏性变更分两步（先扩后收，expand-contract）
- 命名：`snake_case`；索引 `idx_<table>_<cols>`；外键 `fk_<table>_<col>`

## 7. Definition of Ready / Done（团队契约）

**DoR**：任务有验收标准、依赖已识别、估时已评审、UI 有设计稿或参照（Plane 截图/Element 组件）。
**DoD**：代码合入 main；单测/集测通过；API 文档更新；E2E 覆盖核心路径；性能无回退（k6 冒烟）；文档同步；演示环境可验。
