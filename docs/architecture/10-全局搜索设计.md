# 10 · 全局搜索设计（S8）

> 对应 Sprint 8；PRD §9.4 落地规格

## 1. 架构

```
issue/doc/page 变更事件 ──▶ es-indexer(worker) ──bulk──▶ ES
                                                        ▲
前端 ──▶ GET /api/v1/search?q=... ──▶ 语法解析器 ──▶ ES bool query
                                    （类 JQL）
管理 ──▶ make reindex ──▶ 全量从 PG 重建（别名切换零停机）
```

索引三枚：`ydsz_issues` / `ydsz_pages` / `ydsz_docs`；routing = workspace_id；别名 `ydsz_issues_current` 支持蓝绿重建。

## 3. 查询语法（类 JQL 子集 v1）

```
query      := orExpr
orExpr     := andExpr (OR andExpr)*
andExpr    := factor (AND factor | factor)*          -- 空格隐式 AND
factor     := NOT factor | '(' orExpr ')' | clause | phrase
clause     := field op value
field      := project|type|status|priority|severity|assignee|reporter|
              label|module|sprint|version|due|created|updated
op         := : | = | != | > | >= | < | <= | in
value      := word | "quoted" | (v1, v2) | me | currentUser() | now(-7d)
phrase     := 裸关键词（走 title^3 + description + comments multi_match）
```

示例：
```
登录页 闪退                              → 全文
project:YD status:todo assignee:me       → 结构化
type:defect severity>=3 created>now(-7d) → 范围
"支付回调" AND module:支付               → 短语+字段
```

实现：`pkg/searchql` 手写递归下降解析器（~300 行），产出 ES bool query AST；解析失败降级为纯全文查询（不报错打断用户）。
权限：query 强制注入 `workspace_id` + 用户可见 project_id 集合 filter（RLS 在搜索层的等价物）。

## 4. 索引同步

- 事件驱动：issue.updated → 拉取最新聚合文档 → `index` 操作（版本号覆盖，天然幂等）。
- 失败处理：Redis Streams 重试 → 死信 → 对账 Job（每 10min 扫 `updated_at > last_indexed` 兜底）。
- 重建：`reindex` 命令扫 PG → bulk（2000/批）→ 新索引 → 切别名 → 删旧。
- comments 内联进 issue 文档（冗余但免 join；评论上限内联 50 条摘要）。

## 5. 前端交互

- 入口：顶栏搜索框 + **Ctrl/Cmd+K 命令面板**（对齐 Plane power-k）。
- 结果页：左侧过滤器（类型/项目/状态/优先级/日期），右侧按类型分组结果（每组 10 条 + 查看更多）；关键词 `<mark>` 高亮。
- 搜索建议：输入防抖 300ms，返回 identifier 精确匹配 + title 前缀匹配（completion suggester，Phase 2 后补，v1 用 match_phrase_prefix）。
- 历史：localStorage 最近 20 条 + 服务端收藏（SearchQuery）。

## 6. 降级策略

ES 不可用 → 自动降级 PG `to_tsvector`（`idx_issues_fts`）+ 精确过滤，响应头 `X-Search-Degraded: true`，前端提示"高级语法暂不可用"。健康检查纳入 `/readyz`。
