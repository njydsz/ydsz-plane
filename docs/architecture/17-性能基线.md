# 17 · 性能基线与压测

> 定义 ydsz-plane 的性能目标、压测脚本、基线记录与回归流程。

## 1. 性能目标（README 已声明）

| 指标 | 目标值 |
|------|--------|
| 页面加载 P95 | ≤ 2s |
| API 响应 P95 | ≤ 200ms |
| 并发用户数 | ≥ 1000 |
| 单项目工作项 | ≥ 100 万 |
| 可用性 SLA | ≥ 99.9% |

## 2. 压测工具

使用 **k6**（Grafana 出品）。脚本位于 `scripts/k6/`：

- `smoke.js`：冒烟 + 基线压测（预热→爬坡→峰值→冷却），覆盖登录、工作项 CRUD、Sprint/Version/States 查询。

## 3. 运行方式

```bash
# 本地冒烟（需后端已启动并 seed）
k6 run scripts/k6/smoke.js

# 指定环境
k6 run scripts/k6/smoke.js -e API_URL=https://staging.example.com/api/v1

# 完整并发压测（1000 并发目标）
k6 run scripts/k6/smoke.js -e VUS=1000
```

## 4. 内置阈值（Thresholds）

`smoke.js` 内置的断言门禁，不满足即压测失败：

```js
thresholds: {
  'ydsz_api_duration': ['p(95)<200', 'p(99)<500'], // 业务接口 P95<200ms
  'ydsz_api_errors':   ['rate<0.01'],              // 错误率 < 1%
  'http_req_duration': ['p(95)<500'],              // 全局 P95<500ms
}
```

## 5. 基线记录

| 日期 | 场景 | 并发 | API P95 | 错误率 | 结论 |
|------|------|------|---------|--------|------|
| 待首测 | smoke | 100 | - | - | 待运行 |

> 每次里程碑发布前更新基线，对比上版判断性能回退。

## 6. 回归流程

1. 每次**性能敏感改动**（SQL、索引、缓存策略、中间件）后运行 `smoke.js`。
2. 对比当前基线：若 P95 回退 > 10%，触发 Review 定位原因。
3. 关键查询需 `EXPLAIN ANALYZE` 验证索引命中。
4. 数据库达到 10 万级数据后，建议补建大数据量压测数据脚本。

## 7. 与 CI 集成（可选）

可将 k6 作为独立 job 加入 CI（在 staging 环境按需触发），非每次 push 必跑（避免消耗资源）：

```yaml
# .github/workflows/perf.yml（按需触发）
on:
  workflow_dispatch:
  schedule:
    - cron: '0 2 * * 0' # 每周日凌晨
```
