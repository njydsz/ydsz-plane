# 17 · 性能基线与压测

> 定义 ydsz-plane 的性能目标、压测脚本、基线记录与回归流程。

## 1. 性能目标（README 已声明）

| 指标 | 目标值 |
|------|--------|
| 页面加载 P95 | ≤ 2s |
| API 响应 P95 | ≤ 200ms |
| 并发用户数 | ≥ 1000 |
| 单项目工作项 | ≥ 100 万 |
| 可用性 SLA | ≥ 99.9% |

## 2. 压测工具

使用 **k6**（Grafana 出品）。脚本位于 `tests/perf/`：

- `smoke-test.js`：冒烟测试（1 VU / 1 迭代）——验证核心端点可用性与鉴权链路。
- `load-test.js`：负载测试（10→100 VU 渐进）——模拟典型工作日负载，内置 P95<200ms 断言。
- `stress-test.js`：压力测试（200 VU 恒定 3 分钟）——探测系统上限与瓶颈。

## 3. 运行方式

```bash
# 本地冒烟（需后端已启动并 seed）
k6 run tests/perf/smoke-test.js

# 指定环境
k6 run -e BASE_URL=https://staging.example.com/api/v1 tests/perf/load-test.js

# 指定测试账号
k6 run -e BASE_URL=https://staging.example.com/api/v1 \
       -e TEST_USER_EMAIL=admin@example.com -e TEST_USER_PASSWORD='xxxx' \
       tests/perf/load-test.js

# 完整三件套（冒烟 → 负载 → 压力），等价于 Makefile 的 perf-smoke / perf-load / perf-stress
make perf-smoke && make perf-load && make perf-stress
```

## 4. 内置阈值（Thresholds）

`load-test.js` 内置的断言门禁，不满足即压测失败：

```js
thresholds: {
  'http_req_duration': ['p(95)<200', 'p(99)<500'],   // 全局 P95<200ms
  'http_req_failed':    ['rate<0.01'],                // 全局错误率 < 1%
  'ydsz_api_errors':    ['rate<0.01'],                // 业务接口错误率 < 1%
  'ydsz_issue_list_duration':   ['p(95)<150'],        // 工作项列表 P95<150ms
  'ydsz_issue_detail_duration': ['p(95)<100'],        // 工作项详情 P95<100ms
  'ydsz_wb_summary_duration':   ['p(95)<200'],        // 工作台汇总 P95<200ms
}
```

## 5. 基线记录

| 日期 | 场景 | 并发 | API P95 | 错误率 | 结论 |
|------|------|------|---------|--------|------|
| 待首测 | smoke | 1 | - | - | 待运行 |
| 待首测 | load | 100 | - | - | 待运行 |
| 待首测 | stress | 200 | - | - | 待运行 |

> 每次里程碑发布前更新基线，对比上版判断性能回退。
>
> **S7.9 执行要点**：先用 `make seed-scale COUNT=100000` 造 10 万级数据，
> 再按冒烟 → 负载 → 压力顺序运行三件套，回填上表并归档至 `docs/perf/`。

## 6. 回归流程

1. 每次**性能敏感改动**（SQL、索引、缓存策略、中间件）后运行 `make perf-smoke`。
2. 对比当前基线：若 P95 回退 > 10%，触发 Review 定位原因。
3. 关键查询需 `EXPLAIN ANALYZE` 验证索引命中。
4. 数据库达到 10 万级数据后，使用 `scripts/seed-scale` 造数并执行完整三件套。

## 7. 与 CI 集成（可选）

可将 k6 作为独立 job 加入 CI（在 staging 环境按需触发），非每次 push 必跑（避免消耗资源）：

```yaml
# .github/workflows/perf.yml（按需触发 + 每周日 02:00）
on:
  workflow_dispatch:
  schedule:
    - cron: '0 2 * * 0' # 每周日凌晨
```
