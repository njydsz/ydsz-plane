## 5. HTTP 中间件链详解

### 5.1 全局中间件（Engine 层，按注册顺序执行）

注册位置：`internal/interfaces/http/router.go` → `NewEngine()`

```
请求进入
   │
   ▼
SecurityHeaders()     — 8 项安全响应头（CSP/HSTS/X-Frame-Options/COOP/CORP/Permissions-Policy/...）
   │
   ▼
RequestID()           — 生成或透传 X-Request-ID（16 字节随机 hex）
   │
   ▼
Recovery(log)         — panic 恢复 + 记录堆栈
   │
   ▼
CORS(origins)         — 跨域（允许 5173/5174/8080 + localhost/127.0.0.1）
   │
   ▼
AccessLog(log)        — 请求日志（method/path/status/duration）
   │
   ▼
MetricsMiddleware()   — Prometheus RED 指标（请求数/延迟/状态码分布）
   │
   ▼
[路由匹配]
```

### 5.2 工作空间级中间件（嵌套）

```
RequireAuth(principalParser)     — 认证（JWT 或 API Token 双通道）
   │   └─ 解析成功：写入 CtxUserID / CtxAuthKind / CtxAuthScopes
   │   └─ 解析失败：401
   ▼
RateLimit(redis, 100/min, "user:{id}")  — 用户级令牌桶限流
   │
   ▼
RequireWorkspaceParam()          — 解析 workspace_id（422 无效格式）
   │   └─ 写入 CtxWorkspaceID
   ▼
RequirePermissionFromDB(rbacStore, perm)  — DB-backed RBAC 权限校验
   │   └─ ResolveMembership → RoleHasPermission
   │   └─ API Token scope 二次收敛
   │   └─ 写入 workspace_role / workspace_is_owner / workspace_permissions
   ▼
RequireProjectParam()            — 解析 project_id（422 无效格式）
   │   └─ 写入 CtxProjectID
   ▼
[Handler]
```

### 5.3 中间件依赖关系图

```
RequireAuth ─┬─ jwt.ParseAccess()
             └─ apiTokenSvc.ResolvePrincipal() （fallback）

RequirePermissionFromDB ── rbacStore.ResolveMembership()
                       └─ rbacStore.RoleHasPermission()
                       └─ apitoken.ScopeCovers() （仅 API Token 路径）
```

### 8.2 Outbox 投递链路

```
DB Transaction
   └─ INSERT domain_events (outbox 表)
       │
       ▼
Outbox Relay (goroutine)
   └─ 轮询 outbox 表 → 发布到 plane.events topic
       └─ published_at 标记 → 防止重复投递

   ├─ notification-consumer  → 生成站内通知

   ├─ search-indexer        → 增量同步搜索文档
   ├─ automation-evaluator  → 执行匹配规则
   ├─ metrics-recorder      → 写入指标快照
   └─ ws-fanout             → Redis Pub/Sub → WebSocket 推送到客户端
```

| Automation Cron | 每分钟 | — | 1 分钟 | `RunScheduledCron` |
| Automation Event | 事件驱动 | — | 实时 | `RunConsumer` |

## 15. 关键架构不变量（DoD 清单）

1. **认证双通道**：所有公共 API 同时支持 Session Cookie 和 API Token（ydz_ 前缀）
2. **RBAC DB-backed**：所有工作空间级路由使用 `RequirePermissionFromDB`（非旧版内存矩阵）
3. **Outbox 投递**：所有领域事件经 Outbox → Relay → RabbitMQ，API 层不直连 MQ
4. **API Token scope 收敛**：即使 RBAC 角色允许，Token scope 不足也 403
5. **幂等定时任务**：所有 Cron 通过 DB `ON CONFLICT` 保证幂等 + DayJitter 避免多实例并发
6. **软删除全表一致**：所有业务表通过 `deleted_at` 软删除，回收站 30 天
7. **统一错误信封**：handler 层统一写 `{"error":{...}}`，嵌套 request_id
8. **WebSocket 限流**：每用户 3 连接 / 每 IP 10 / 全局 1000
9. **安全响应头 8 项**：SecurityHeaders 中间件全路由注入
10. **OpenAPI 注解完整**：swaggo 注解覆盖全部公共端点，dev 环境暴露 Swagger UI

## 17. 维护约定

1. **新增领域服务**：在 `internal/application/<domain>/` 新建目录，在 `cmd/api/main.go` 装配并在 `router.go` 添加注册函数
2. **新增前端视图**：在 `web/src/views/<domain>/` 新建 `.vue`，在 `router/index.ts` 添加路由
3. **新增 API**：在 `web/src/api/services/` 新增 Service 模块，在对应后端 handler.go 注册
4. **新增迁移**：`sql/` 递增编号，上 `make migrate` 验证
5. **新增事件**：在对应 Service 的 DB 事务中 `INSERT domain_events`；在 worker `Register` 对应消费
6. **新增权限点**：`auth/rbac.go` 追加 `PermXxx` 常量，数据库 `role_permissions` 预置种子记录
7. **新增配置项**：`config/config.go` + `Load()` 默认值 + 本文档 §10.2 更新
