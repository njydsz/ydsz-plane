## 二、关键修复

### P0-1 前端 ESLint 门禁全量失效（存量）
- **根因**：`eslint.config.js` 仅引入 `eslint-plugin-vue`，未配置 TypeScript 解析器，所有含类型语法的 `.vue` 文件报 `Parsing error`，`pnpm lint --max-warnings 0` 无法通过，CI `web-lint` 门禁形同虚设。
- **修复**：安装 `@typescript-eslint/parser`，配置 `vue-eslint-parser` + TS parser；随后自动修复 115 处格式告警，逐类收敛剩余 16 处（require-default-prop / require-explicit-emits / no-v-html）。
- **结果**：`eslint . --max-warnings 0` 0 error / 0 warning 通过。

### P0-2 评论存储型 XSS（存量）
- **根因**：`comment_service.go` 将前端传入的 `content_html` 原样落库，前端 `CommentItem` 用 `v-html` 渲染——恶意 `<script>`/事件属性可形成存储型 XSS。
- **修复**：引入 `github.com/microcosm-cc/bluemonday`（Go 社区标准白名单清洗器），基于 `StrictPolicy` 新建 `comment_sanitize.go`：仅放行 TipTap 排版标签，强制剥离 script/img/iframe/事件属性，链接仅 http/https/mailto 并强制 `nofollow + noreferrer`；`Create`/`Update` 均清洗后落库。配套 4 组单测（脚本剥离/富文本保留/链接属性/空串）。

### P0-3 SearchView 存量编译错误（阻塞 typecheck）
- **根因**：`allHits` 计算属性引用未定义变量 `value`；`filteredHits` 定义后未被使用。
- **修复**：删除无用计算属性；`v-html` 拆分——highlight（服务端 ts_headline 转义生成）保留 v-html 并加行内豁免注释，`item.name` 回退改插值渲染（消除 self-XSS 面）。

### P0-4 压测流水线路径失效（存量）
- **根因**：`perf.yml` 与 `Makefile` 均引用不存在的 `scripts/k6/smoke.js`（实际脚本在 `tests/perf/`，且环境变量命名不一致）。
- **修复**：CI 扩展为 smoke → load → stress 三步完整流程；Makefile 新增 `perf-smoke / perf-load / perf-stress / perf-json` 目标；`scripts/k6/smoke.js` 改写为迁移占位脚本；文档 `17-性能基线.md` 同步。
