# 16 · 依赖安全治理

> 定义 ydsz-plane 的第三方依赖安全扫描、漏洞响应与升级策略，对标大厂供应链安全实践。

## 1. 扫描工具链

| 栈 | 工具 | CI 作业 | 频率 |
|----|------|---------|------|
| Go | `govulncheck` | `ci.yml → go-security` | 每次 push/PR |
| Web | `pnpm audit --prod` | `ci.yml → web-audit` | 每次 push/PR |
| 全栈 | GitHub CodeQL | `codeql.yml` | push/PR + 每周一 |

## 2. 门禁策略

- **Go**：`govulncheck` 发现任一漏洞即阻断合并（`exit 1`）。
- **Web**：`pnpm audit --prod` 存在高危（high/critical）漏洞即阻断。
- **CodeQL**：`security-and-quality` 查询集，发现的安全问题在 PR 中标记。

> 首次接入若历史漏洞较多，可先以 `warning`（不阻断）观察一轮，再收紧为阻断。

## 3. 漏洞响应 SLA

| 严重级别 | 响应时限 | 修复时限 | 处理 |
|---------|---------|---------|------|
| Critical | 24h | 7 天 | 立即升级/缓解，必要时发安全公告 |
| High | 3 天 | 14 天 | 常规升级流程 |
| Medium/Low | 30 天 | 下个里程碑 | 排期处理 |

## 4. 升级流程

1. **识别**：CI 扫描或公告发现漏洞。
2. **评估**：确认是否被实际调用路径影响（`govulncheck` 自带可达性分析）。
3. **升级**：仅升级受影响依赖，避免盲目整体升级。
4. **回归**：跑通 `make lint && make test`。
5. **记录**：在 CHANGELOG 记录升级版本。

## 5. 常用命令

```bash
# Go：扫描当前模块
go run golang.org/x/vuln/cmd/govulncheck@latest ./...

# Web：审计生产依赖
cd web && pnpm audit --prod

# 查看可升级的依赖
cd web && pnpm outdated
```
