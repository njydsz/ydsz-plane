## 二、关键验证

### P0-1 认证安全基线

| 安全控制 | 实现 | 位置 |
|---------|------|------|
| 密码哈希 | bcrypt cost=12（≈250ms） | auth/service.go |
| 认证错误模糊化 | 不区分用户/密码错误 | Login() 返回 ErrInvalidCredentials |
| Token 类型隔离 | access/refresh 不可互用 | ParseAccess 校验 Kind |
| 签名密钥隔离 | 启动期自动生成 dev 密钥；生产强制外部注入 | config.go |
| 弱密码拦截 | Register 强制 ≥8 位 | auth/service.go:151 |
| 账号状态校验 | is_active 软禁用 | Login/Refresh 路径 |
| 密码重置 Token | SHA-256 哈希落库（仅明文出现在邮件） | invitation.go |

### P0-2 RBAC 中间件设计

```text
RequireAuth → RequireWorkspaceParam → RequirePermission → handler
      ↓               ↓                      ↓
   JWT/Token      解析 ws_id          角色权限 + API Token scope 双检
```

**API Token 收敛防线**：即使用户角色拥有某权限，API Token 必须有对应 scope 才能通过（GitHub PAT 模型）。

### P0-3 审计覆盖

所有写入操作均调用 AuditSvc.RecordFromGin：
- 工作空间：Create / Update / Archive / MemberChange
- 邀请：Invite / Accept / Revoke
- 成员：Remove / ChangeRole
