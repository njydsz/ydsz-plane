## 二、关键修复

### P0-1 dump 序列缺陷（影响所有新数据写入）

- **根因**：Navicat dump 先 `CREATE SEQUENCE "<table>_id_seq"`，PG 建 `GENERATED ALWAYS AS IDENTITY` 列时检测到同名序列，自动改用 `"<table>_id_seq1"`。dump 中 86 处 `setval('"public"."<table>_id_seq"', N, ...)` 全部设置在**错误序列**上，identity 真实序列从未同步——有 seed 数据的表（users/workspaces）新插入直接撞主键（实测 `Key (id)=(3) already exists`）。
- **修复**：全部 setval 改写为动态解析：
  ```sql
  SELECT setval(pg_get_serial_sequence('public.<table>', 'id'),
                (SELECT COALESCE(MAX(id), 0) FROM public.<table>) + 1, false);
  ```
  空表取 1、有数据表取 max+1，防重命名、防撞键。
- **验证**：全新库实测——新 user 插入 id=6 ✓、新 workspace 插入 id=4 ✓（修复前撞 5/3）。
