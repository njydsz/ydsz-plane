# 04 · 数据模型设计（S2–S4 数据层基线）

> 对应 Sprint 2/3/4 的数据层实施规格
> 参考：PostgreSQL 官方最佳实践、阿里《数据库设计规范》、Plane 数据模型

---

## 1. 全局约定

| 约定 | 规格 |
|------|------|
| 主键 | `id BIGINT GENERATED ALWAYS AS IDENTITY`（不外泄）；对外暴露用 `public_id UUID`（仅需要外部引用的表） |
| 租户列 | 所有业务表含 `workspace_id BIGINT NOT NULL`，为复合索引首列，RLS 依据 |
| 时间戳 | `TIMESTAMPTZ`，`created_at/updated_at` 全表必备；`updated_at` 由触发器维护 |
| 软删除 | `deleted_at TIMESTAMPTZ NULL`，唯一索引需带 `WHERE deleted_at IS NULL` |
| 乐观锁 | 高频并发编辑表（issues/sprints/versions）含 `version INT NOT NULL DEFAULT 1`，UPDATE 条件带 version，冲突返回 409 |
| 枚举 | 应用层校验 + DB `CHECK` 约束双保险；可扩展配置（状态/模块）走配置表 |
| 金额/工时 | 工时 `NUMERIC(8,2)` 小时制；故事点 `SMALLINT` |
| JSONB | 仅用于真·动态结构（viewport、layout、payload、environment）；可过滤字段必须提升为列 |

## 3. 关键表 DDL（定稿级）

### 3.1 issues（系统最核心的表）

```sql
CREATE TABLE issues (
    id              BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    public_id       UUID NOT NULL DEFAULT gen_random_uuid(),
    workspace_id    BIGINT NOT NULL REFERENCES workspaces(id),
    project_id      BIGINT NOT NULL REFERENCES projects(id),
    sequence_id     BIGINT NOT NULL,                     -- 项目内自增，配合 identifier 展示 YD-123
    type_code       TEXT NOT NULL CHECK (type_code IN ('requirement','task','defect')),
    parent_id       BIGINT REFERENCES issues(id),
    depth           SMALLINT NOT NULL DEFAULT 1 CHECK (depth BETWEEN 1 AND 3),
    name            TEXT NOT NULL,
    description_json    JSONB,
    description_html    TEXT,
    description_stripped TEXT,                           -- tsvector 检索源
    state_id        BIGINT NOT NULL REFERENCES states(id),
    priority        TEXT NOT NULL DEFAULT 'none'
                    CHECK (priority IN ('urgent','high','medium','low','none')),
    -- defect 专有
    severity        SMALLINT CHECK (severity BETWEEN 1 AND 5),
    found_phase     TEXT CHECK (found_phase IN ('unit','integration','uat','production','customer')),
    found_version_id BIGINT REFERENCES versions(id),
    fix_version_id   BIGINT REFERENCES versions(id),
    root_cause_category TEXT CHECK (root_cause_category IN ('requirement','technical','environment','data')),
    verifier_id     BIGINT REFERENCES users(id),
    environment     JSONB,
    reproduce_steps JSONB,                               -- {steps, expected, actual} 富文本
    -- task 专有
    category        TEXT,                                -- frontend/backend/qa/doc...
    actual_effort   NUMERIC(8,2),
    remaining_effort NUMERIC(8,2),
    delay_reason    TEXT CHECK (delay_reason IN ('requirement_change','resource','blocked','other')),
    -- requirement 专有
    source          TEXT,                                -- customer/internal/competitor
    -- 通用
    point           SMALLINT CHECK (point BETWEEN 0 AND 12),
    estimate_point_id BIGINT REFERENCES estimate_points(id),
    sprint_id       BIGINT REFERENCES sprints(id),
    version_id      BIGINT REFERENCES versions(id),      -- 首次发布版本
    progress        SMALLINT NOT NULL DEFAULT 0 CHECK (progress BETWEEN 0 AND 100),
    start_date      DATE,
    target_date     DATE,
    completed_at    TIMESTAMPTZ,
    is_draft        BOOLEAN NOT NULL DEFAULT FALSE,
    sort_order      DOUBLE PRECISION NOT NULL DEFAULT 65535,  -- 看板拖拽排序
    created_by      BIGINT NOT NULL REFERENCES users(id),
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    deleted_at      TIMESTAMPTZ,
    version         INT NOT NULL DEFAULT 1,
    UNIQUE (project_id, sequence_id),
    UNIQUE (public_id) WHERE deleted_at IS NULL,
    CONSTRAINT defect_required CHECK (
        type_code <> 'defect' OR (severity IS NOT NULL AND found_phase IS NOT NULL)
    )
);

-- 索引（前缀 workspace_id 支撑 RLS 后扫描）
CREATE INDEX idx_issues_project_state   ON issues(workspace_id, project_id, state_id)  WHERE deleted_at IS NULL;
CREATE INDEX idx_issues_project_sprint  ON issues(workspace_id, project_id, sprint_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_issues_parent          ON issues(parent_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_issues_target_date     ON issues(workspace_id, project_id, target_date) WHERE deleted_at IS NULL AND completed_at IS NULL;
CREATE INDEX idx_issues_updated         ON issues(workspace_id, updated_at DESC);
CREATE INDEX idx_issues_fts             ON issues USING gin(to_tsvector('simple', coalesce(name,'') || ' ' || coalesce(description_stripped,'')));  -- ES 不可用时的降级
CREATE INDEX idx_issues_sort            ON issues(project_id, state_id, sort_order);   -- 看板
```

> 说明：PG `to_tsvector` 中文用 `simple` 配置仅作降级兜底；正式全文检索走 ES + IK（见文档 10）。

### 3.2 RLS 策略模板

```sql
ALTER TABLE issues ENABLE ROW LEVEL SECURITY;
ALTER TABLE issues FORCE ROW LEVEL SECURITY;   -- owner 也受控，仅靠 bypass 角色迁移
CREATE POLICY tenant_isolation ON issues
    USING (workspace_id = current_setting('app.workspace_id', true)::bigint)
    WITH CHECK (workspace_id = current_setting('app.workspace_id', true)::bigint);
```

连接获取规约（中间件强制）：
```go
tx.Exec(ctx, "SELECT set_config('app.workspace_id', $1, true)", workspaceID)  -- 事务级
```
应用使用专用低权账号 `ydsz_app`（非表 owner）；迁移用 `ydsz_migrator`（BYPASSRLS）。

### 3.3 发号器（sequence_id，对标 Plane sequence 方案）

```sql
CREATE TABLE project_sequences (
    project_id BIGINT PRIMARY KEY REFERENCES projects(id),
    next_value BIGINT NOT NULL DEFAULT 1
);
-- 发号：单语句原子
UPDATE project_sequences SET next_value = next_value + 1
WHERE project_id = $1 RETURNING next_value - 1;
```
并发安全、无间隙保证要求低（允许跳号），性能 O(1)。

### 3.4 状态流转规则表

```sql
CREATE TABLE state_transitions (
    id              BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    workspace_id    BIGINT NOT NULL,
    project_id      BIGINT NOT NULL REFERENCES projects(id),
    type_code       TEXT NOT NULL,                 -- 按工作项类型独立流转集
    from_state_id   BIGINT NOT NULL REFERENCES states(id),
    to_state_id     BIGINT NOT NULL REFERENCES states(id),
    required_fields JSONB NOT NULL DEFAULT '[]',   -- 如缺陷 resolved 时要求 root_cause_category
    allowed_roles   JSONB NOT NULL DEFAULT '[]',   -- 空 = 继承项目角色默认
    UNIQUE (project_id, type_code, from_state_id, to_state_id)
);
```

### 3.5 Outbox 与幂等

```sql
CREATE TABLE domain_events (
    id              BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    workspace_id    BIGINT NOT NULL,
    aggregate_type  TEXT NOT NULL,
    aggregate_id    BIGINT NOT NULL,
    event_type      TEXT NOT NULL,                 -- issue.status_changed ...
    payload         JSONB NOT NULL,
    occurred_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    published_at    TIMESTAMPTZ
);
CREATE INDEX idx_events_unpublished ON domain_events(id) WHERE published_at IS NULL;

CREATE TABLE processed_events (                    -- 消费者幂等
    consumer TEXT NOT NULL,
    event_id BIGINT NOT NULL,
    processed_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (consumer, event_id)
);

CREATE TABLE idempotency_keys (                    -- API 写幂等
    key         TEXT PRIMARY KEY,
    user_id     BIGINT NOT NULL,
    response    JSONB,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## 4. 大表与容量策略

| 表 | 量级预估（单项目100万工作项） | 策略 |
|----|------------------------------|------|
| issues | 100万×N 项目 | 暂不分区；`updated_at` 归档冷数据；索引如 §3.1 |
| issue_activities | 工作项×20+ | **按月 RANGE 分区**，12 个月后转冷备 |
| webhook_logs / rule_executions | 高频 | 按月分区 + 30 天 TTL（分区 drop 即清理） |
| domain_events | 高频 | 已发布事件每日归档任务清理（保留 7 天） |
| notifications | 用户×高频 | 按月分区；已读 90 天清理 |
| sprint_snapshots | sprint×天 | 不分区，JSONB 压缩存储（TOAST） |

分区统一用 PG16 原生声明式分区，分区维护脚本 `scripts/partition-maintenance.sh` 每月 1 日预建未来 3 个月分区（cron 容器执行）。

## 5. 迁移与种子数据

- 迁移编号 `NNNN_description.up/down.sql`，CI 校验升序与 down 非空。
- 种子分两级：`seed_min`（系统必需：默认状态模板/角色权限点）随迁移内置；`seed_demo`（演示数据）手动执行。
- 项目创建时由应用服务从**状态模板表**复制状态集（三套：研发流/缺陷流/需求评审流），模板存 `state_templates` JSONB。

## 6. 信创方言适配点

| PG 特性 | 达梦/人大金仓替代 |
|---------|------------------|
| `gen_random_uuid()` | 应用层生成 UUID 传入 |
| `ILIKE` | 统一封装 `dialect.LikeInsensitive()` |
| JSONB 操作符 `@>` `?` | 收敛到 `jsonx` 包，方言实现 |
| `RETURNING` | 达梦 8 支持；金仓兼容 |
| RLS | 达梦提供 VPD 等价；金仓支持 RLS；应用层租户过滤始终保留（双保险） |
| 声明式分区 | 三者均支持 RANGE 分区 |

约束：ORM 不用重型框架，统一 `pgx` + 手写 SQL（sqlc 生成类型安全代码），方言差异集中在 `internal/infrastructure/persistence/dialect`。
