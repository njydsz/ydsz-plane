# 15 · 发布管理

> 本文档定义 ydsz-plane 的版本规范、发布流程与发布门禁，对标 GitHub Flow / 语义化版本实践。

## 1. 版本规范（SemVer）

采用 [语义化版本](https://semver.org/lang/zh-CN/)，格式 `MAJOR.MINOR.PATCH`：

| 位 | 何时递增 | 示例 |
|----|---------|------|
| MAJOR | 不兼容的 API/数据变更 | `1.0.0` |
| MINOR | 向后兼容的功能新增 | `0.2.0` |
| PATCH | 向后兼容的缺陷修复 | `0.1.1` |

预发布版本后缀：`-alpha.x` / `-beta.x` / `-rc.x`。

## 2. 分支策略与发布模型（Trunk-Based）

```
main（受保护，永远可发布）
 ├── feature/xxx     → PR → squash merge 到 main
 ├── fix/xxx         → PR → squash merge 到 main
 └── release/v0.x    → 仅在发布冻结期从 main 拉出，只接受 cherry-pick 修复
```

- 日常开发全部基于 `main`，通过 PR + CI 门禁合并。
- 发布冻结期从 `main` 拉出 `release/v0.x` 分支，只合入阻塞性修复。
- 正式发布后打 tag `v0.x.0`，并在 `release/v0.x` 上继续 patch。

## 3. 发布门禁（Definition of Done）

任一 PR 合并前必须通过：

- [ ] 后端 `golangci-lint` 通过
- [ ] 后端 `go test ./... -race` 通过，覆盖率不低于当前基线
- [ ] `govulncheck` 无高危漏洞
- [ ] 前端 `eslint` + `vue-tsc` 通过
- [ ] 前端 `vitest` 通过，`pnpm build` 成功
- [ ] 前端 `pnpm audit --prod` 无高危依赖
- [ ] 至少 1 人 Code Review 通过（含 AI 审查）
- [ ] 遵守 [Conventional Commits](../../CHANGELOG.md) 提交规范

## 4. 发布执行步骤

1. **确认门禁**：`make lint && make test && make build` 全绿。
2. **更新 CHANGELOG**：将 `[Unreleased]` 内容迁移到对应版本区块，补日期。
3. **打标签**：
   ```bash
   git tag -a v0.1.0 -m "release: v0.1.0"
   git push origin v0.1.0
   ```
4. **触发发布**：推送 tag 自动触发 `.github/workflows/release.yml`，构建产物并创建 GitHub Release。
5. **发布说明**：Release Notes 摘要主要特性 / 修复 / 迁移注意事项。
6. **回滚预案**：保留上一个 tag 的镜像，通过 `docker compose` 指定镜像 tag 快速回滚。

## 5. 分支保护配置（GitHub Settings）

在 GitHub 仓库 **Settings → Branches → Add rule** 为 `main` 启用：

- **Require a pull request before merging**：至少 1 个 approve
- **Dismiss stale pull request approvals when new commits are pushed**：开
- **Require status checks to pass before merging**：勾选 CI 的 `go-lint` / `go-test` / `go-security` / `web-lint` / `web-test-build` / `web-audit` / `analyze (go)` / `analyze (javascript-typescript)`
- **Require branches to be up to date before merging**：开
- **Do not allow bypassing the above settings**：开（管理员同样受约束）
- **Require signed commits**：可选（合规团队建议开）

## 6. 代码审查

- **AI 审查（可选）**：`.github/workflows/ci.yml` 中的 `code-review` 作业使用 `@alibaba-group/open-code-review`。需在仓库 Secrets 配置 `OCR_LLM_URL` / `OCR_LLM_TOKEN` / `OCR_LLM_MODEL` 后启用；未配置时该作业自动跳过。
- **规则文件**：项目级审查规则见 `.opencodereview/rule.json`（含 SQL 注入、RLS 越权、事务边界、N+1、XSS 等专项）。
- **安全分析**：`.github/workflows/codeql.yml` 每周定时 + PR 触发，覆盖 Go 与 JS/TS。
