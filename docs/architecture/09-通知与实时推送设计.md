# 09 · 通知与实时推送设计（S7/S9）

> 对应 Sprint 7（站内信+WS）、Sprint 9（邮件/IM/摘要）
> PRD §9.3 落地规格

---

## 1. 管道总览

```
领域事件(Outbox→Redis Streams)
   │
   ▼
notification-dispatcher（worker）
   1. 事件 → 通知对象解析（recipient resolver）
   2. 订阅过滤（NotificationSubscription + 默认规则矩阵）
   3. 免打扰时段检查（dnd → 转 digest 队列）
   4. 渠道展开：in_app / email / im
   5. digest 模式：聚合表暂存，定时合并发送
   ▼
notifications 表（站内信，读写分离缓存未读数）
channel-sender: email(SMTP) / wecom / dingtalk / feishu
ws-fanout: Redis Pub/Sub → api WS 连接 → 前端铃铛红点
```

## 2. 接收人解析规则（默认矩阵，PRD §9.3）

| 事件 | 默认接收人 | 站内 | 邮件 | IM |
|------|-----------|:----:|:----:|:--:|
| issue.updated（我创建的） | created_by | ● | ○ | ● |
| issue.assigned | 新 assignees | ● | ● | ● |
| comment.created（我评论过的） | 评论参与者 | ● | ● | ○ |
| mention | 被 @ 人 | ● | ● | ● |
| sprint.ending_soon（剩 1 天） | 迭代参与者 | ● | ● | ● |
| version.released / version.status_changed | 版本参与者 | ● | ● | ● |
| automation.failed（连续 3 次） | 规则创建者+项目 admin | ● | ● | ● |

- 用户级覆盖：`/me/notification-settings` 按 项目×事件类型×渠道 三维开关。
- 自我豁免：操作者本人不接收自己触发的通知。

## 3. 数据模型

```sql
notifications(id, workspace_id, recipient_id, actor_id, issue_id,
              event_type, title, body, data JSONB,        -- data: 跳转上下文
              is_read BOOL, read_at, created_at)          -- 按月分区
notification_subscriptions(user_id, scope[workspace|project], ref_id,
              event_type, channel, is_enabled,            -- 显式覆盖行
              digest[realtime|daily|weekly], dnd_start, dnd_end, tz)
notification_digests(id, user_id, channel, payload JSONB,
              scheduled_for, sent_at)                     -- 摘要暂存
```

未读数：Redis `unread:{uid}` 计数（事件递增/已读递减），DB 为准对账。

## 4. 渠道实现

| 渠道 | 实现 | 要点 |
|------|------|------|
| 站内信 | notifications 表 + WS 推送 | 列表游标分页；全部已读；点击跳转 data.url |
| 邮件 | SMTP（配置化），`html/template` 模板，中英双语 | 异步发送；失败重试×3；退信记录 |
| 企业微信 | 群机器人 Webhook / 应用消息（配置 token） | markdown 卡片 |
| 钉钉 | 自定义机器人（加签） | markdown 格式 |
| 飞书 | 自定义机器人（签名校验） | 消息卡片 |
| Slack/Teams | 通用 Webhook | Phase 3 |

IM 通道抽象 `im.Sender` 接口；配置存 `notification_channels`（workspace 级，secret 加密存储）。

## 5. 摘要（digest）与免打扰

- `digest=daily`：每日 08:30（用户时区）合并暂存事件为单条摘要（按项目分组）。
- 免打扰时段内（如 22:00–08:00）：realtime 也降级为 digest。
- 高优豁免：mention、automation.failed 不受免打扰限制（可配置）。

## 6. WebSocket 细节

- 单连接订阅 workspace 频道 + `/me` 个人频道；Redis Pub/Sub 扇出到多 api 副本。
- 消息类型：`notification.new`（铃铛+1）、`issue.updated`（看板失效）、`presence`（Phase 3）。
- 断线重连后拉 `GET /me/notifications?unread=true&since=<last_ts>` 补齐。

## 7. 性能与可靠性

- dispatcher 批量消费（Redis Streams，100/批）；收件人展开异步化（大项目 500+ 成员时 fan-out 任务化）。
- 发送失败：渠道级重试×3（指数退避）→ 死信记录 + 告警指标 `notification_send_failures_total`。
- 通知风暴保护：同一 issue 5 分钟内多次更新合并为一条（Redis 去重窗口）。
