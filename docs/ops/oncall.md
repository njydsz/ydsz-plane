# On-Call 轮值约定

> 配套 [运维手册](./README.md) · [告警处置 Runbook](./runbook.md)

---

## 1. 目标

- P0 告警 5 分钟内响应、1 小时内恢复（或止血）
- P1 告警 30 分钟内响应
- 每月不低于 99.9% 可用性 SLO

---

## 2. 轮值表结构

| 角色 | 职责 | 时间 |
|------|------|------|
| oncall-a（主） | 第一时间响应、处置、升级 | 1 周轮换 |
| oncall-b（备份） | 15 分钟未响应自动升级 | 1 周轮换 |
| sre 主管 | 发布审批、重大变更终审 | — |

轮值表建议使用 PagerDuty / 飞书 oncall / 钉钉轮值机器人维护，与 Alertmanager webhook 联动。

---

## 3. On-Call 值班包

值班开始前准备：
- [ ] VPN /堡垒机可达生产环境
- [ ] 本地安装 `docker`, `kubectl`, `pgcli`, `redis-cli`
- [ ] 熟悉本手册 Runbook 与最近一个月 incident report
- [ ] 联系信息更新到 oncall-a 配置

值班期间：
- [ ] 告警手机 24h 开机
- [ ] 每班次开始查看交接日志（前一班异常与未结项）

---

## 4. 应急响应流程

```
告警触发
  │
  ▼
oncall-a 5min 内认领（静默告警）
  │
  ▼
查 Runbook 对应处置
  ─ 15min 内止血 → 记录 → 交班日志
  ─ 超时未止血 → 升级 oncall-b + 启动 war room
  │
  ▼
业务恢复？
  ─ 是 → 事后复盘（48h 内出 incident report）
  ─ 否 → 升级 SRE 主管 + 决策（回滚/停机处理）
```

---

## 5. 停机 / 决策红线

以下操作需 SRE 主管 + Admin 双人审批：
- `DROP TABLE` / 不可逆 DB 操作
- 主机重启 / 节点回收
- 域名 / 证书切换
- 主动限流 / 降级 / 停服

---

## 6. Incident Report 模板

每次 P0/P1 事件后 48h 内提交：

```markdown
# INC-YYYYMMDD-XXX

- 发现时间：
- 恢复时间：
- 影响范围：
- 触发原因：
- 处置经过：
- 改进项（至少 3 条）：
  - Runbook 更新
  - 监控补强
  - 代码/配置修复
- 负责人：
```

归档路径：`docs/ops/incidents/YYYY-MM-DD-XXX.md`

---

## 7. 降级策略

| 降级手段 | 触发条件 | 损失 |
|----------|----------|------|
| 关闭搜索建议 | ES 不可用 / lag >30s | 搜索体验降级，主业务不受影响 |
| 限制创建工作项 QPS | DB 写入 P95 >1s | 限流提示 |
| 停服维护 | 高危数据安全事件 | 全站不可用 |
