## 一、核心结论总览

本次从**数据库表设计、后端测试覆盖、前后端接口贯通**三个维度对 ydsz-plane 进行了全面深度扫描，共发现 **77 个具体问题**（P0=17项, P1=31项, P2=21项, P3=8项）。

### 三维度健康度评分

| 维度 | 评分 | 核心差距 |
|------|:---:|------|
| 数据库表设计 | **B-** (78/100) | 分区表零实现、RLS 写绕过、7 张表缺失高频索引 |
| 后端测试覆盖 | **D+** (42/100) | 文件覆盖率仅 18%，核心 handler/service 零测试 |
| 前后端贯通 | **C** (58/110) | Swagger 覆盖率 5.1%、orval 从未执行、多处类型漂移 |

### 三大"断链"现状

1. **Swagger → TS 类型断链**：后端 287 个 @Summary 注解 vs swagger.yaml 仅 8 条路径 vs 前端 0 个自动生成类型
2. **测试金字塔塌方**：单元测试集中在 issue 纯函数（76 个），handler/service 层几乎空白，集成测试基座未启用
3. **Schema → 索引断桥**：文档设计标注的 5 张分区表 + 20+ 高频索引全部未落实到 DDL

## 二、P0 紧急项（建议 1 周内完成）

### 🔴 P0-1：RLS 写绕过漏洞修复

**文件**：`sql/V26.09.26__rls_and_extensions.sql`

当前 RLS 策略只有 `USING`（读保护）没有 `WITH CHECK`（写保护），攻击场景：

```sql
SET app.current_tenant = '123';
INSERT INTO task (..., tenant_id) VALUES (..., 456);  -- 成功写入错误租户！
```

**修复**：在新迁移文件 `V26.10.01__rls_add_with_check.sql` 中为所有 71 张表 ALTER POLICY 添加 `WITH CHECK`。

---

### 🔴 P0-2：intake_channels / intake_issues 纳入 RLS

含 `tenant_id` 的业务表未启用 RLS。需追加 RLS 策略和行级访问控制。

---

### 🔴 P0-3：notifications 表补 workspace_id 字段

设计文档要求 `workspace_id BIGINT NOT NULL` 但 SQL 缺失该字段，通知无法按工作空间隔离。

```sql
ALTER TABLE notifications ADD COLUMN workspace_id BIGINT NOT NULL DEFAULT 0;
```

需同步更新相关查询和索引。

---

### 🔴 P0-4：Swagger 流水线重建（第一优先级工程改进）

```bash
# 执行一次完整重建
make swagger        # swag init 重跑
pnpm gen:types      # orval 生成 TS 类型
git diff --stat     # 审查 diff
```

审查后提交，消除 swagger.yaml 与 Go 源码的 287 vs 8 条路径的巨大差距。

---

### 🔴 P0-5：dashboardApi 清理 5 个 404 接口

**文件**：`web/src/api/services/dashboard.ts` (行 233-263)

这 5 个 method（listWidgets/createWidget/updateWidget/deleteWidget/getOverview）调用后端不存在的接口，生产必 404。

**建议**：移除前端空方法，数据改由已有的 data-endpoint 拉取（burndown、velocity、alerts 等）。

---

### 🔴 P0-6：ReproduceSteps 类型对齐

**前端**发结构化对象 `{steps, expected, actual}`，**后端**用 `json.RawMessage` 收货但不解析，导致数据损坏。

**修复**：后端 `updateIssueRequest.ReproduceSteps` 改为 `map[string]any` 或具名 struct。

---

### 🔴 P0-7：统一错误码双命名体系

`codes.go` 27 个常量与 `errs.go` 哨兵变量格式不一致（如 `AUTH.UNAUTHORIZED` vs `AUTH_ERROR`），前端 i18n 永远匹配不到。

**建议**：合并 `codes.go` → `errs.go`，所有哨兵变量使用统一 code string 格式。

---

### 🔴 P0-8：引入 testcontainers-go 启用集成测试

```bash

go get github.com/testcontainers/testcontainers-go/modules/postgres@v0.33.0
```
